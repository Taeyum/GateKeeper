# A페이 인프라 변경관리 규정 (가상)

> GateKeeper 데모용 가상 규정이다. 조항마다 rule_id가 있고, MCP Resource `rules://CHG-01` 형태로 조항 하나씩 읽는다.
> 이 문서가 판정의 원본이다. `rules.json`은 같은 내용을 코드가 읽기 쉽게 옮긴 것이고, 둘이 어긋나면 이 문서를 따른다.

## 0. 용어

| 용어 | 뜻 |
|---|---|
| 일반 변경 | 표준 변경과 유효한 긴급 변경을 뺀 모든 변경. 변경관리자 승인이 필요하다 |
| 표준 변경 | 3장 "표준 변경 목록"에 있는 사전 승인된 저위험 변경. 위반이 없으면 자동 승인된다 |
| 긴급 변경 | 진행 중인 장애를 해결하기 위한 변경. CHG-07을 따른다 |
| 사내망 | 10.0.0.0/8. 이 밖의 출발지는 외부로 본다 |
| 작업 구간 | 요청에 적힌 시작 시각부터 종료 시각까지. 종료 시각이 없으면 시작 후 1시간으로 본다 |
| 요청 시각 | 변경요청이 접수된 시각(submitted_at) |

**변경 유형**

| 유형 | 코드 | 포함 범위 |
|---|---|---|
| 방화벽 | `firewall` | 방화벽 규칙 추가, 수정, 삭제 |
| 배포 | `deploy` | 애플리케이션 배포, 설정 파일 배포, 재시작이 필요한 설정 변경 |
| DB 변경 | `db_change` | DB와 캐시 같은 데이터 저장소의 스키마, 인덱스, 파라미터, 버전 변경 |
| 표준 변경 | `standard` | 3장의 목록에 있는 변경만 해당 |

## 1. 판정 기준

| 구분 | 조항 | 판정 |
|---|---|---|
| 금지 조항 | CHG-01, CHG-02, CHG-03, CHG-06, CHG-10 | 하나라도 위반하면 **반려** (재제출 필요, 통과 가능한 대안을 함께 안내) |
| 보완 조항 | CHG-04, CHG-05, CHG-08, CHG-09 | 금지 위반 없이 보완 조항만 위반하면 **조건부 승인** (조건을 달아 승인) |
| 위반 없음 | - | 일반 변경은 **승인**, 표준 변경은 **자동 승인** |

- CHG-07(긴급 변경 절차)은 위반 여부가 아니라 면제와 사후 보고 여부를 정한다.
- 위험도(5장)는 판정을 바꾸지 않는다.

## 2. 조항

### CHG-01 배포 금지 시간대

- 구분: 금지
- 적용 대상: 방화벽, 배포, DB 변경 (표준 변경 제외)
- 내용: 금요일 18:00부터 월요일 09:00까지는 일반 변경을 하지 않는다. 작업 구간이 이 시간대와 조금이라도 겹치면 위반이다.
- 예외: 유효한 긴급 변경(CHG-07)
- 예시: 금요일 20:00 시작은 위반. 금요일 16:00~17:00은 통과. "주말에"처럼 날짜만 있고 시각이 없어도 주말 전체가 금지 시간대라 위반이다.

### CHG-02 전체 대역 오픈 금지

- 구분: 금지
- 적용 대상: 방화벽
- 내용: 방화벽 규칙의 출발지에 0.0.0.0/0(또는 ::/0)을 허용하지 않는다. 출발지를 적지 않았거나 "외부 전체", "아무 데서나", "외부에서 접근 가능하게"처럼 범위를 특정하지 않은 요청은 0.0.0.0/0으로 본다.
- 예외: 없음 (긴급 변경도 적용)
- 범위 밖: 외부 공개 웹(web-01, web-02)의 443 포트는 로드밸런서에서 관리하며 이 규정의 방화벽 변경 대상이 아니다.

### CHG-03 DB 포트 외부 노출 금지

- 구분: 금지
- 적용 대상: 방화벽 중 목적지 포트가 DB 포트(5432, 3306)인 경우
- 내용: DB 포트는 사내망에서만 연다. 외부 출발지는 CMDB `partners`에 등록된 파트너 IP를 /32로 지정한 경우만 예외로 한다. 출발지를 적지 않으면 외부 전체로 보아 위반이다.
- 예외: 없음 (긴급 변경도 적용)
- 예시: 203.0.113.10/32(B페이먼츠 등록 IP)는 통과. 203.0.113.0/24는 위반. 10.30.2.15는 사내망이라 이 조항과 무관하다.
- 참고: 요청에 포트가 없으면 대상 DB의 CMDB 기본 포트로 본다.

### CHG-04 롤백 계획 필수

- 구분: 보완
- 적용 대상: 배포, DB 변경
- 내용: 변경을 되돌리는 절차를 한 줄 이상 적는다. (예: "이전 이미지 태그로 재배포", "인덱스 DROP", "설정 원복 후 재시작")
- 조건부 대안: 롤백 절차를 제출하는 조건으로 승인한다.

### CHG-05 Tier-1 사전 공지

- 구분: 보완
- 적용 대상: 방화벽, 배포, DB 변경 중 대상이 Tier-1인 경우
- 내용: Tier-1 서비스 변경은 작업 시작 24시간 전까지 요청한다. 요청 시각이 작업 시작 24시간 전보다 늦으면 위반이다.
- 예외: 유효한 긴급 변경(CHG-07)
- 조건부 대안: 작업 시작을 요청 시각 + 24시간 이후로 미룬다. 미룬 시각이 다른 금지 조항(CHG-01, CHG-10)에 걸리지 않는지 함께 본다.

### CHG-06 동시간 변경 금지

- 구분: 금지
- 적용 대상: 모든 유형 (표준 변경 포함)
- 내용: 같은 대상에 이미 승인된 변경(변경 캘린더의 `scheduled_changes`)이 있으면 작업 구간이 겹치면 안 된다.
- 예외: 없음 (긴급 변경도 적용)

### CHG-07 긴급 변경 절차

- 구분: 절차
- 적용 대상: 요청자가 긴급이라고 표시한 변경
- 내용: 긴급 변경은 진행 중인 장애 티켓 번호(`INC-연도-번호`)를 적는다. 티켓이 `open_incidents`에 열린 상태(open)로 있고, 그 장애의 대상 서비스에 요청 대상이 포함되면 **유효한 긴급 변경**이다.
- 유효한 긴급 변경은 CHG-01, CHG-05, CHG-10을 면제받고, 나머지 조항은 그대로 검사한다. 실행 후 24시간 안에 사후 보고한다.
- 티켓이 없거나, 종료됐거나, 대상이 다르면 일반 변경으로 처리한다. 이것 자체는 위반이 아니다.

### CHG-08 테스트 증적

- 구분: 보완
- 적용 대상: 배포, DB 변경
- 내용: 운영 반영 전 스테이징 테스트 결과를 첨부하거나 테스트 완료를 적는다. "사후 첨부", "테스트 예정"은 증적 없음으로 본다.
- 조건부 대안: 테스트 결과를 제출하는 조건으로 승인한다.

### CHG-09 임시 오픈 만료일 필수

- 구분: 보완
- 적용 대상: 방화벽 중 출발지가 외부인 경우
- 내용: 허용 기한을 적고, 기한은 최대 30일이다. 기한이 없거나("기간 미정" 포함) 30일을 넘으면 위반이다. "작업 끝나면 바로 닫음"처럼 종료 시각이 정해진 경우는 그 시각을 기한으로 본다.
- 조건부 대안: 기한을 30일 이내로 지정해 승인한다.

### CHG-10 배포 동결 기간

- 구분: 금지
- 적용 대상: 모든 유형 (표준 변경 포함)
- 내용: 변경 캘린더의 `freeze_periods`에 등록된 동결 기간에는 그 범위(scope)에 속한 서비스를 변경하지 않는다. 범위가 `*`이면 모든 서비스가 대상이다. 작업 구간이 동결 기간과 조금이라도 겹치면 위반이다.
- 예외: 유효한 긴급 변경(CHG-07)

## 3. 표준 변경 목록

| ID | 이름 | 조건 |
|---|---|---|
| STD-01 | 로그 레벨 변경 | 재시작 없이 로그 레벨만 바꾸는 경우. 다른 설정을 함께 바꾸거나 재시작이 필요하면 일반 변경(배포)이다 |
| STD-02 | 인증서 갱신 | 같은 도메인의 인증서를 만료 30일 이내에 교체하는 경우 |

- 표준 변경에는 CHG-06, CHG-10만 적용한다.
- 표준 변경은 정책 검사만 하고 영향도와 이력 검사는 생략한다.

## 4. 변경 유형별 필수 항목

| 변경 유형 | 필수 항목 | 근거 조항 |
|---|---|---|
| 방화벽 | 대상과 포트, 출발지 IP, 허용 기한(출발지가 외부일 때), 사유 | CHG-02, CHG-03, CHG-09 |
| 배포 | 작업 시간, 롤백 계획, 스테이징 테스트 결과 | CHG-01, CHG-04, CHG-08 |
| DB 변경 | 작업 시간, 롤백 계획, 테스트 결과, Tier-1이면 24시간 전 요청 | CHG-04, CHG-05, CHG-08 |
| 표준 변경 | 대상, 작업 시간 | 3장 목록, CHG-06, CHG-10 |

## 5. 위험도

- 기본값은 CMDB 등급을 따른다. Tier-1은 높음, Tier-2는 중간, Tier-3은 낮음.
- 과거 이력에 **같은 서비스 + 같은 변경 유형**으로 난 장애(`outcome`이 "장애")가 있으면 한 단계 올린다. 최대는 높음이다.
- 위험도는 판정을 바꾸지 않는다. 승인자 결재함 정렬과 "유사 장애 있음" 표시에만 쓴다.
- 표준 변경은 영향도와 이력 검사를 생략하므로 위험도를 매기지 않는다.
